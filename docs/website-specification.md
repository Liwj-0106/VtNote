# VtNote 界面与交互设计

状态：当前实现规格
校准日期：2026-08-19

## 设计目标

VtNote 是内容处理工作台，不是下载器控制台或模型管理后台。界面应让用户在三个问题上保持清楚：输入是什么、将生成什么、现在进行到哪一步。

设计原则：

- 默认路径短：新建处理 → 内容库 → 导出。
- 生成选择真实控制流水线；字幕不隐含 AI。
- 状态和错误使用可读文本，不只依赖颜色或内部错误码。
- 高级配置留在设置，不把 Provider 参数堆到首页。
- 已完成成果在失败任务中仍然可见和可导出。

## 信息架构

### 可见导航

| 入口 | 路由 | 职责 |
|---|---|---|
| 新建处理 | `/` | B 站链接或本地音视频启动台 |
| 内容库 | `/tasks` | 任务列表、阶段进度、终态与导出 |
| 设置 | `/settings` | 默认生成/导出、ASR 和 AI 笔记配置 |

### 辅助路由

| 路由 | 当前状态 |
|---|---|
| `/settings/connections` | 从设置进入，管理腾讯云 ASR |
| `/settings/ai-connections` | 从设置进入，管理 TokenHub 模型 |
| `/tasks/:id` | 已实现详情、取消、重试和执行摘要，但内容库当前没有入口 |
| `/setup` | 已实现 readiness 页面，当前无导航入口 |
| `/settings/storage` | 已实现存储/回收站页面，当前无导航入口 |

辅助路由在正式开放前必须补入口和用户旅程测试；代码存在不等于产品已开放。

## 页面规格

### 新建处理

- 标题：`把音视频变成字幕和笔记`。
- 链接/上传使用 tab，不同时展示两个大型表单。
- 链接输入只承诺 B 站公开链接；提交前先探测并规范化。
- 上传使用原生 file input，接受当前后端支持的音视频扩展，并展示上传进度。
- 页面不再提供“音频/字幕/笔记”三档单选；默认生成内容在设置中维护。
- 创建成功统一进入 `/tasks`，由内容库行内展示进度。
- 配置或探测失败时留在当前页并给出操作建议。

### 内容库

- 每行展示标题、创建时间、当前阶段/终态和导出按钮。
- 活动阶段按 source、transcribe、translate、notes 顺序聚合；有数值进度时显示百分比，否则显示已完成阶段数或 indeterminate 动画。
- `waiting_external` 显示“等待云端”，不能伪造本地百分比。
- 终态文案至少区分完成、完成有提醒、失败、已取消。
- 任何终态都可以打开成果弹窗；弹窗根据 `/outcomes` 禁用不存在的音频/字幕/笔记。
- 列表分页每次 30 条；存在活动任务时前台快速轮询、后台降频、失败退避。

### 导出弹窗

- 三类成果分别选择，不把“全部导出”写成已完成状态。
- 格式默认值来自 `vtnote.preferences.v1`。
- 音频：M4A/MP3；字幕：SRT/TXT；笔记：Markdown/TXT。
- 未生成的类型禁用并说明，而不是让下载请求后才失败。
- 下载使用浏览器正常文件下载，不把导出内容写入 localStorage。

### 设置

设置按三个组展示：

1. 处理与导出：默认生成与导出类型、音频/字幕/笔记格式。
2. 语音识别：默认 ASR、管理 ASR。
3. AI 笔记：默认模型、管理模型。

规则：

- 默认类型至少保留一个；损坏或空偏好恢复为“字幕原文”。
- 只有已测试、已授权的 profile 可以作为默认处理服务。
- 选中但未完成验证的连接可以显示在下拉框中，但不可作为可用 profile。
- 保存成功使用短暂 `aria-live` 状态，不弹阻塞式成功对话框。
- 文案明确：“未选择 AI 笔记时不会安排大模型总结”。

### 连接管理

- ASR 页面只创建腾讯云录音文件识别连接；密钥输入不回显已保存值。
- AI 页面当前只创建腾讯云 TokenHub 连接，模型固定为当前支持集。
- 验证操作可能真实请求并计费，必须有明确确认语义。
- 删除连接前二次确认；级联删除 profile，但不删除历史任务快照和已生成成果。

## 视觉系统

当前 token 由 `frontend/src/styles/tokens.css` 定义：

| 用途 | 当前值 |
|---|---|
| 画布 / 侧栏 / 表面 | `#f7f5f0` / `#efece6` / `#fcfbf8` |
| 主文本 / 次文本 | `#262421` / `#6f6a63` |
| 品牌强调 | terracotta `#b95232`，深色 `#7e3826` |
| 成功 / 警告 / 危险 | `#2f6953` / `#81520f` / `#9a342d` |
| 字体 | Segoe UI、Microsoft YaHei UI/system；标题可用 Georgia/Noto Serif SC |
| 圆角 | 8 px / 12 px |
| 侧栏 | 展开 232 px，收起 64 px |
| 内容最大宽度 | 1120 px |
| 动效 | 160–200 ms，并尊重 reduced-motion |

不引入通用 UI 框架。重复组件应抽到 React 组件和 CSS token，而不是复制页面结构。当前 `components.css` 体积过大，后续按 shell/form/library/dialog 拆分，但不在仅文档清理中机械重排样式。

## 响应式与可访问性

- 375 px 宽度不应产生页面横向滚动。
- 桌面侧栏可折叠；移动端使用 drawer、scrim、初始焦点和 Escape 关闭。
- 所有主要操作键盘可达，focus ring 可见。
- tabs、dialog、progressbar、status 使用正确语义和可读 label。
- indeterminate progress 不提供伪造 `aria-valuenow`。
- 错误、成功和禁用原因不能只用颜色表达。
- Playwright + axe 不允许 serious/critical 可访问性违规进入发布基线。

## 浏览器持久化

只允许保存 UI 偏好：

- `vtnote.sidebar.collapsed`
- `vtnote.preferences.v1`

不得保存密钥、任务、字幕、笔记、用户原始路径、provider 响应或 CSRF token。

## 后续设计决策

在新增页面前，优先解决：

1. 内容库是否开放任务详情入口；
2. active 媒体保留与清理是否进入设置；
3. 多字幕轨选择和来源标识如何展示；
4. ASR/AI 连接管理如何抽成配置驱动共用组件；
5. 隐藏路由若不开放，是否删除对应代码和测试。

旧 A/B/C HTML 原型、云端页面架构候选和会话式 UI 决策日志已经删除；本文件是当前唯一界面基线。
